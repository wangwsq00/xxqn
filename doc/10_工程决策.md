# 工程决策（M1）

> 本文只记录已拍板的实现约束，不改写 `doc/modules/*` 玩法正文。

对照日期：2026-09-21。

## 技术栈

| 项 | 决策 |
|----|------|
| 运行形态 | **浏览器 Web**（H5）。后期可评估小程序；**不做独立 App**。 |
| 语言 / 构建 | TypeScript（strict）+ Vite |
| 渲染 | **Phaser 3**（色块占位即可） |
| 不采用 | Godot、原生双端壳 |
| 包管理 | npm 或 pnpm 均可（见仓库根 `README.md`） |
| 代码位置 | 仓库根目录（`src/`、`index.html`），保留 `doc/` 不动 |

产品文档仍写「挂机手游」；客户端首版按浏览器交付，与上述栈一致。

## 战斗布局（5v5）

权威规则见 `doc/modules/05_战斗系统.md`：攻守双方最多各 5 个单位；位置从上到下 **4 - 2 - 1 - 3 - 5**，**1 号位在中间**。

补充实现约束（文档未写死、现已锁定）：

1. **主角永远占据我方 1 号位（中间）**。
2. 前期不必凑满 5 个友方空位；空位渲染为占位槽。
3. 后续灵宠 / 傀儡 / 分身填入其余友方槽（2–5），不挤占主角中位。
4. M1 试炼战：仅主角上阵，对位 1–2 名敌人，验证行动条与胜负。

## 行动条工程常量

`05_战斗系统.md` 只规定「速度决定移动、先到终点者行动、事后**重置位置**」，未给条长。工程默认：

| 常量 | 值 | 说明 |
|------|----|------|
| `ATB_MAX` | **1000** | 满条后置 0，不保留溢出连动 |
| 逻辑帧 | 10 tick/s | 每 tick `ATB += 速度` |
| 开场 | 全员 ATB = 0 | — |
| 同帧满条次序 | 速度降序 → 位置号 1→5 → 我方先于敌方 | 文档未写时的工程默认 |

## 洞府挂机（M1）

权威玩法：`01_角色系统.md` 的灵气/秒与聚灵阵倍率；`02_挂机系统.md` 的自动修炼 / 离线收益（正文数值仍待补）。

| 项 | M1 落地 |
|----|---------|
| 灵气 | 炼气 1/秒起，按大境界倍增；× (1 + 聚灵阵加成) |
| 离线 | 单次间隔封顶 **8 小时**，超出丢弃 |
| 领取 | 洞府展示速率与待领取，点「领取洞府收益」入账 |
| 存档 | 浏览器 LocalStorage 键 `xxqn-save-v1` |

灵石小时公式仓库未写。M1 **工程默认**（填可玩缺口，**不是**聊天稿）：炼气境 **1 灵石/分钟**，各大境界倍率与灵气基础倍率相同；聚灵阵不加速灵石。明确不采用 `50+N×18`。

## 聚灵阵（M1）

权威玩法：`01_角色系统.md` 的 1–10 级、每级 +10% 灵气、灵石价格表。公式仍是 `基础灵气/秒 × (1 + 聚灵阵加成)`。

| 项 | M1 落地 |
|----|---------|
| 未购买 | 0 级，加成 0 |
| 购买 / 升级 | 洞府入口「聚灵阵」，消耗灵石升 1 级；先按旧速率结算待领取 |
| 价格 / 加成 | **沿用角色文档表**（1 级 100 灵石 +10% … 10 级 5,000,000 灵石 +100%） |
| 开局灵石 | 仓库未写。M1 **工程默认**新档 **600 灵石**（100+500），刚好可买 1 级并升到 2 级 |
| 存档 | 同一 `xxqn-save-v1` 的 `player.gatheringArrayLevel` |
| 展示 | 洞府修炼速率旁显示等级；购买后灵气/秒立即按新加成计算 |

旧存档若已有 `stones` 字段则不补发开局灵石。明确不采用聊天稿「无聚灵阵」。

## 装备（M1）

权威玩法：`09_装备系统.md` 的 **6 部位**（武器 / 上衣 / 下装 / 鞋子 / 首饰左 / 首饰右）与炼气境武器名「木剑」；属性叠加入 `01_角色系统.md` 公式 `攻资 × (基础+装) × 1.0`。

文档**没有**装备数值表。M1 **工程默认**（保守、可玩）：

| 项 | 值 | 说明 |
|----|----|------|
| 木剑装备攻击力 | **+12** | 炼气基础攻 100 的 12%；只加攻，不加暴击 |
| 开局 | 背包放入 1 把未穿戴木剑 | 旧存档迁移同样补发 |
| 掉落 | 试炼胜利若尚未拥有木剑则入包 | 已拥有则不再掉 |
| 其它五槽 | UI 占位 | 无物品、无属性 |
| 存档 | 同一 `xxqn-save-v1` 的 `equipment` | 穿戴状态随 LocalStorage 持久化 |

明确不采用聊天稿三槽、凡/灵/玄品阶、开局铁剑。

## 明确不采用

与设计源冲突的聊天稿口径一律忽略，包括但不限于：单人手推约 80 关、1 主动 + 2 被动、ATB 溢出连动、战斗蓝量「灵气」、Godot、通关才能挂机、按关号算灵石、装备三槽/凡灵玄、无聚灵阵。
