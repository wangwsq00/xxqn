## 技术栈

| 项 | 决策 |
|----|------|
| 运行形态 | **浏览器 Web**（H5）。后期可评估小程序；**不做独立 App**。 |
| 语言 / 构建 | TypeScript（strict）+ Vite |
| 渲染 | **Phaser 3**（M1 已接入国漫立绘 PNG，见 [`docs/M1_asset_list.md`](../docs/M1_asset_list.md)；空位仍用淡色槽） |

产品文档仍写「挂机手游」；客户端首版按浏览器交付，与上述栈一致。

## 战斗布局（5v5）

权威规则见 `doc/modules/05_战斗系统.md`：攻守双方最多各 5 个单位；位置从上到下 **4 - 2 - 1 - 3 - 5**，**1 号位在中间**。

补充实现约束（文档未写死、现已锁定）：

1. **主角永远占据我方 1 号位（中间）**。
2. 前期不必凑满 5 个友方空位；空位渲染为占位槽。
3. 后续灵宠 / 傀儡 / 分身填入其余友方槽（2–5），不挤占主角中位。
4. M1 试炼 / 心魔：主角居中；若已装备灵宠则占我方 **2 号位**；对位 1–2 名敌人。未出战则该槽为空。

## 行动条工程常量

`05_战斗系统.md` 只规定「速度决定移动、先到终点者行动、事后**重置位置**」，未给条长。工程默认：

| 常量 | 值 | 说明 |
|------|----|------|
| `ATB_MAX` | **1000** | 满条后置 0，不保留溢出连动 |
| 逻辑帧 | 10 tick/s | 每 tick `ATB += 速度` |
| 开场 | 全员 ATB = 0 | — |
| 同帧满条次序 | 速度降序 → 位置号 1→5 → 我方先于敌方 | 文档未写时的工程默认 |

## 洞府挂机（M1）

权威玩法：`01_角色系统.md` 的灵气/秒与聚灵阵倍率；`02_挂机系统.md` 的自动修炼 / 离线收益（正文数值仍待补）。

| 项 | M1 落地 |
|----|---------|
| 灵气 | 炼气 1/秒起，按大境界倍增；× (1 + 聚灵阵加成) |
| 离线 | 单次间隔封顶 **8 小时**，超出丢弃 |
| 领取 | 洞府展示速率与待领取，点「领取洞府收益」入账 |
| 存档 | 浏览器 LocalStorage 键 `xxqn-save-v1` |

灵石小时公式仓库未写。M1 **工程默认**（填可玩缺口，**不是**聊天稿）：炼气境 **1 灵石/分钟**，各大境界倍率与灵气基础倍率相同；聚灵阵不加速灵石。明确不采用 `50+N×18`。

## 聚灵阵（M1）

权威玩法：`01_角色系统.md` 的 1–10 级、每级 +10% 灵气、灵石价格表。公式仍是 `基础灵气/秒 × (1 + 聚灵阵加成)`。

| 项 | M1 落地 |
|----|---------|
| 未购买 | 0 级，加成 0 |
| 购买 / 升级 | 洞府入口「聚灵阵」，消耗灵石升 1 级；先按旧速率结算待领取 |
| 价格 / 加成 | **沿用角色文档表**（1 级 100 灵石 +10% … 10 级 5,000,000 灵石 +100%） |
| 开局灵石 | 仓库未写。M1 **工程默认**新档 **600 灵石**（100+500），刚好可买 1 级并升到 2 级 |
| 存档 | 同一 `xxqn-save-v1` 的 `player.gatheringArrayLevel` |
| 展示 | 洞府修炼速率旁显示等级；购买后灵气/秒立即按新加成计算 |

旧存档若已有 `stones` 字段则不补发开局灵石。明确不采用聊天稿「无聚灵阵」。

## 多关试炼（M1 续 / M2 默认）

权威玩法：战斗模块只列副本 / PVP / 公会，**未写**线性关卡表。本切片在既有单场试炼上扩成 **3 关推进**（工程默认，**不是**聊天稿约 80 关）。

| 项 | M1 落地 |
|----|---------|
| 关卡 | **3 关**：第1关野修试炼、第2关邪修试炼、第3关魔修试炼 |

## 境界 / 修为（M1）

权威玩法：`01_角色系统.md` 灵气作经验、小境界自动升层、消耗公式、九层心魔突破。

| 项 | M1 落地 |
|----|---------|
| 范围 | 同一大境内 **1–9 层自动升**（开局炼气）；**九层心魔战**可破下一境（见下节） |
| 消耗 | 炼气 1→2 = **100**，其后 ×1.2；大境界 1→2 = 上一境 8→9 ×2 |
| 入账 | 洞府「领取洞府收益」把待领取灵气写入钱包后 **自动消耗并升层**；读档时若钱包已满同样自动升 |
| 上限 | 1–8 层：下一层消耗的 100%；9 层：突破需求的 **200%**，超出截断 |
| 展示 | 洞府显示 `炼气境N层`、修为进度条与「升至下一层」；九层改为突破灵气条 |
| 存档 | 同一 `xxqn-save-v1` 的 `player.realmMajor` / `realmLayer` / `lingqi` |

小境界仍不破大境。本切片**仍不做**：突破丹药、50% 成功率掷骰、小境界 +5 / 大境界全资质 +10（无资质存档）。战斗基础攻仍按**大境界**（炼气 100、筑基 150），不随小层刷新。

明确不采用聊天稿 10 层小境界、凡人圆满另开一境。

## 心魔 / 破境（M1）

权威玩法：`01_角色系统.md` 大境界突破两阶段（心魔战 → 成功率掷骰 + 丹药）。文档未给心魔副本编制、数值与失败扣血。

| 项 | M1 落地 |
|----|---------|
| 入口 | 洞府「挑战心魔」。炼气（及之后各大境）**九层**且钱包灵气 ≥ 突破需求 **100%** 可点 |
| 战斗 | 复用试炼 ATB 场景；敌方仅 1 名「心魔」占 1 号中位。数值为**工程默认**（按当前大境基础值缩放：血≈基础×2、攻≈×0.85），保证炼气九层可打过 |
| 胜利 | **直接**进入下一大境 **一层**，灵气清零（对齐文档成功「灵气清零」）。不发试炼灵石、不掉木剑 |
| 失败 | **软重试**：不扣灵气、不改境界，可立即再战（对齐文档心魔战失败「提升后重试」，而不是第二阶段失败扣 100% 灵气） |
| 渡劫九层 | 不可再破 |
| 存档 | 同一 `xxqn-save-v1` 的 `player.realmMajor` / `realmLayer` / `lingqi`；挂机、聚灵阵、装备、试炼奖励与升层逻辑保持既有行为 |
| 筑基后 | 洞府灵气/秒按大境界表变为 2；试炼/心魔主角基础攻 150 |

**相对文档的缺口 / 有意简化**（填可玩闭环，**不是**聊天稿）：

1. **两阶段收成一战**：文档要求先胜心魔（不扣灵气）再另选时机掷成功率；M1 心魔胜利即破境，不再单独点「突破」。
2. **不做成功率**：基础 50% + 灵气 150%/200% 加成 + 筑基丹等丹药均未实现。
3. **不做资质**：小境界 +5 自由点、大境界全资质 +10 未入存档。
4. **心魔数值**：文档无表；上表为工程默认，未做「必须先强化功法/装备才能打过」的难度门。
5. **第二阶段失败惩罚未用**：文档举例 150% 失败 → 剩 50%；M1 失败走心魔软重试。

明确不采用聊天稿「满修为且打过指定关」。洞府领取、聚灵阵、装备穿戴、试炼 5v5 与关卡灵石、1–9 层自动升保持既有行为。

## 静态部署（GitHub Pages）

权威交付形态仍是浏览器 Web。仓库用 Vite 打出静态 `dist/`，由 `.github/workflows/deploy-pages.yml` 在 **push `main`** 或 **workflow_dispatch** 时发布到 **`gh-pages` 分支**。

| 项 | M1 落地 |
|----|---------|
| 项目页 URL | `https://<owner>.github.io/<repo>/`（本仓库预期 `https://wangwsq00.github.io/xxqn/`） |
| `base` | CI 按仓库名推断；可用 `VITE_BASE` 覆盖。见 `src/deploy/viteBase.ts` |
| 仓库设置 | Pages → Deploy from a branch → `gh-pages` / root（需维护者开一次） |
| 不改 | 玩法、存档键、本地 `npm run dev` / `preview` 仍走根路径 `/` |

## 明确不采用

与设计源冲突的聊天稿口径一律忽略，包括但不限于：单人手推约 80 关、1 主动 + 2 被动、ATB 溢出连动、战斗蓝量「灵气」、Godot、通关才能挂机、按关号算灵石、装备三槽/凡灵玄、无聚灵阵、80 关掉落表、小境界 10 层、《凡剑诀》及聊天稿技能表。
