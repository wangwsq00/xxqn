## 2. 仓库沉默、可吸收的操作补丁（候选，不改玩法）

以下仅填「待补充」或完全未写的**工程向**细节。采用前仍建议负责人点头；默认值可整体乘系数微调，但**不得**借此引入 C 表玩法。

### 2.1 技术栈说明（仓库未选栈）

- 仓库**没有**锁定引擎或语言。  
- 聊天稿建议：TypeScript (strict) + Vite + Phaser 3 + pnpm 或 npm 锁一种；目标现代浏览器。  
- **本附录不把 Phaser 定为强制栈。** 产品定位是「挂机手游」，与「网页优先、不做独立 App」冲突（见 C2/C3）。  
- **待拍板后再写进正文**的选项举例：  
  - 若确认 **H5/浏览器**：可采用 TS + Vite；2D 引擎 Phaser 3 **或等价**（Pixi、自绘 Canvas）均可。  
  - 若确认 **原生/双端手游**：另选 Unity / Cocos / 小游戏容器等，与聊天稿脱钩。  
- 无论哪条：逻辑与渲染分层、关卡/功法/掉落数据驱动、伤害与挂机产出做成纯函数，这些工程原则与仓库设计兼容，可作编码约定（不绑定 Phaser 目录名）。

### 2.2 行动条实现常量（机制仍按仓库「到终点重置」）

仓库只写了「速度决定移动、先到终点者行动、事后重置位置」，未给条长与逻辑帧。

| 常量 | 建议默认 | 说明 |
|------|----------|------|
| `ATB_MAX` | 1000 | 纯实现刻度；**满条后重置为 0**（遵守仓库，不保留溢出连动） |
| 逻辑帧 | 10 tick/s | `本帧位移 = 速度 × (ATB_MAX 的归一系数)`；调参只动速度系数，不改「重置」 |
| 开场 | 全员 0 | 与仓库无冲突 |

**同帧多人满条**（仓库未写）：建议 ① 当前速度降序；② 速度相同按位置号 **1→5**；③ 仍平则攻方先于守方。一次行动：选目标 → 按 1–4 槽自动放功法或普攻 → 结算 → **ATB 置 0**。

### 2.3 挂机/离线（`02_挂机系统.md` 正文仍为「待补充」）

仓库已有：**在线灵气/秒按大境界**、聚灵阵倍率、离线收益这一条目但无数字。

| 项 | 建议补丁 | 明确不采用 |
|----|----------|------------|
| 离线结算上限 | **8 小时**；超出丢弃 | 聊天稿「必须先手打通关才能挂该关」 |
| 同时挂机 | 与自动修炼一致：角色**持续修炼**（非选关挂机） | `灵石/时 = 50+N×18`（依赖不存在的关号 N） |
| 领取 | 回前台/进挂机界面时结算一次 | — |
| 灵气产出 | **仍用** `01_角色系统.md`：`基础灵气/秒 × (1+聚灵阵)` | 不得改成战斗蓝量回复 |
| 灵石/材料/功法 | 仓库未给小时公式 → **不编造**；见第 4 节待决 | 不得套用 80 关掉落表 |

### 2.4 本地存档字段草图（仓库未写）
